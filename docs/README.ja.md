# docs

[English](README.md) | [日本語](README.ja.md)

静的サイトです。ビルド処理はありません。日本語と英語に対応し，`?lang=ja` / `?lang=en` で初期言語を指定できます。クエリがない場合は保存された言語設定，またはブラウザーの優先言語を使います。スクリプトが動かない場合の静的 HTML は英語で，`i18n.js` が読み込み後に切り替えます。

## 公開

公開前にリポジトリのルートから `node docs/test.js` を実行してください。小さな DOM と fetch の代替を使い，応答の検査，言語切り替え，実行中と失敗時の表示を確認します。通信は行わず，DNS 経路，CORS，証明書の信頼，公開環境を検証するものではありません。DNS，VPS，証明書の残りの準備は[配備手順](../poc/deploy/README.md)を参照してください。

1. リポジトリを GitHub に push する。
2. Settings の Pages を開き，Source で Deploy from a branch を選ぶ。ブランチは `main`，フォルダは `/docs`。
3. カスタムドメインに `yes-its-a-problem.iamwonderingif.com` を設定する。`docs/CNAME` に設定済み。
4. Cloudflare で `yes-its-a-problem` の CNAME レコードを作り，値に `<owner>.github.io` を指定する。DNS only にする。
5. Enforce HTTPS を有効にする。

## 設定

`config.js` には `releasesUrl`，`labDomain`，`mitmHost` があります。`releasesUrl` は GitHub の owner/repo に合わせます。`labDomain` と `mitmHost` は検証用ホスト名のままにします。

## チェック

DNS は `v.lab...` 配下のランダムなラベルへ HTTPS で接続します。応答の `token` と `host` が期待値に一致し，`"path":"fake"` なら偽装側，`"path":"true"` なら正規側の HTTPS サーバーという報告を表示します。DNS の問い合わせ自体をブラウザーから観測するものではありません。接続の失敗，リダイレクト，不正な応答は判定不能です。

TLS は `https://login.v.lab.../tls-probe` へ接続します。応答には期待した `host` と，小文字の16進数64文字の `leaf_sha256` が必要です。`"tls":"forged"` には同形式の `issuer_spki_sha256` も必要で，危殆化 CA が署名したリーフ証明書を提示したというサーバー報告を意味します。`"tls":"other"` は別の証明書という報告で，危殆化 CA の証明書を拒否したことにはなりません。ページはブラウザーの相手証明書を読み取れないため，応答の形式を検査するだけで，これらの指紋を接続先の証明書と独立に照合するものではありません。接続の失敗，リダイレクト，分類の欠落や未知値，不正な応答は判定不能です。ブラウザーは証明書エラーをページに渡さないため，拒否と通信の失敗は区別できません。

DNS が `fake` を返すには，偽装側の HTTPS サーバーがランダムな probe 名に対してブラウザーが受理する証明書を提示する必要があります。そうでない場合，ブラウザーが probe の応答を読む前に証明書を拒否します。MITM ホストの証明書は，別に実行する TLS の確認でのみ使います。

結果は別々の DNS と TLS 接続で得た状態を並べます。同じ通信で二段階の攻撃が成立した証拠ではありません。対象の中間 CA は失効済みです。最新の対応状況はページ内の出典を確認してください。結果は使用中のブラウザーだけを示します。

ラボの HTTPS エンドポイントは，設定した TLS コンテキストから直接配信してください。CDN やリバースプロキシで TLS を終端すると，バックエンドの証明書報告は別の接続についての情報になります。静的ページの公開だけではラボの検証になりません。配備後に実際の証明書，CORS 応答，DNS 経路，ブラウザーの挙動を確認してください。

[第三者の公開 DNS 事例の記録](../artifacts/dns-authority-trace-2026-10-24.json)には，外部 NS 名への ADDITIONAL A が含まれています。RFC 9471 の sibling glue ではありません。範囲と来歴は記録内に記載しています。このリポジトリのローカルな権威 DNS レコードの比較とは別の観測であり，DNS から TLS までの攻撃全体を実証するものではありません。
